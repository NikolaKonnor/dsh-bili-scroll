# B站 日报：每周复盘

目标：让推荐越来越懂主人。做法是**你提建议、主人拍板**。画像只有在主人明确同意后才改。

## 模式一：复盘（每周自动跑，或主人说"做一下每周复盘"）

只用 `bili` MCP 服务器的工具，不用 shell、不改任何文件。

1. `memory_profile_read`：读当前画像。
2. `memory_feedback_recent(days=14)`：读最近两周的反馈。
3. `duty_seen_recent(limit=200)`：看最近推过、跳过了什么。
4. 找规律，只看**有证据**的：
   - 同一类内容（方向、形式、UP 主、时长）连续被说"好"或"不好"；
   - 主人的理由里反复出现的词（"太浅""讲得清楚""太长""已经知道了"……）；
   - 画像里标【推测】的条目，有没有被反馈证实或推翻；
   - 说"好"并且理由是关于内容质量的 UP 主，可以提议加进画像第七节"验证过的好 UP 主"；连续两次"不好"的，提议移出去。
5. 用 `memory_proposal_write` 写建议。每条建议包含：
   - **改哪里**：画像第几节、哪一行；
   - **原来**：原文；
   - **建议改成**：新写法；
   - **依据**：引用哪几条反馈（日期 + BV + 主人原话）。
   证据不够的不要提；一次最多 5 条，按把握大小排序。没有值得改的就写"本周没有需要修改的地方"，并说明看了多少条反馈。
6. 用 `owner_send` 给主人发一条短私信（不超过 490 字）：本周收到几条反馈、提了几条建议、最重要的一条是什么，请他在电脑上打开 Codex 说"应用画像建议"来审阅。

## 模式二：应用建议（主人在交互对话里说"应用画像建议"）

1. 读最近一份 `proposals/<日期>.md`（在数据目录里，默认 `~/.bili-agent/proposals/`）和当前画像 `~/.bili-agent/profile.md`。
2. **逐条**念给主人听：改哪里、原来、建议、依据。每条问主人：采纳 / 不采纳 / 改一改。
3. 只把主人采纳的改进画像，改动保持最小，不顺手改别的地方；把"更新于"日期改成今天。
4. 改完把改了哪几处列给主人看。

## 原则

- 画像描述的是**主人自己说的、或者被他的反馈证实的**东西。不要从浏览记录、播放进度、收藏推断他喜欢什么，这些都不可靠（画像第九节）。
- 主人的原话比你的概括重要：引用时照抄。
- 宁可少改。一条错误的修改比一条遗漏的修改危害大。
